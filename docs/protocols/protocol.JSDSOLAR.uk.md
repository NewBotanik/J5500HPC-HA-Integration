## 1. Основні відомості

| Параметр | Значення |
|---|---|
| Інтерфейс | RS232C, роз'єм DB9 «мама» на інверторі |
| Налаштування послідовного порту | **2400 bps, 8 біт даних, без парності, 1 стоп-біт (8N1)** |
| Кодування | Текст ASCII |
| Термінатор запиту | `\r` (CR, 0x0D) |
| Термінатор відповіді | `\r` (CR, 0x0D) |
| Ролі | Головний пристрій (ПК / master) надсилає запит, інвертор відповідає. Інвертор ніколи не надсилає даних з власної ініціативи. Єдиний виняток — рукостискання з платою SNMP/BMS у §11. |
| Тайм-аут відповіді | Інвертор **має відповісти протягом 500 ms** |
| Префікс відповіді з даними | `(` для більшості запитів. `#` для `F` та `I`. `BL` для `BL`. Без префікса для `TCQN`, `DATE` і `TIME`. |
| Результат запису | `ACK\r` означає успіх. `NAK\r` означає відмову (значення поза діапазоном або команда не дозволена в поточному режимі). |
| Роздільник полів | Один пробіл (0x20) |
| Числа | Десяткові фіксованої ширини з доповненням нулями та фіксованою десятковою крапкою (`MMM.M`, `QQQ`, …) |

## 3. Формат кадрів і загальні правила

### 3.1 Запит

```
<COMMAND>[<parameter>]\r
```

- Лише символи ASCII. Літери команд — великі.
- Параметр іде одразу після назви команди, без роздільника: `CHGC020\r`, `TCCV28.3\r`, `SPON1\r`.
- Параметр повинен мати **рівно таку ширину, як у шаблоні**, з доповненням нулями. Наприклад, `<nnn>` → `020`, `<nn.n>` → `28.3`, `<nnnn>` → `0060`.
- Команди калібрування містять знак: `BUN+10\r`, `VR-.5\r`.
- Розширені команди (§11) використовують `\n` усередині кадру: `SNMP\n\r`.

### 3.2 Типи відповідей

| Тип | Формат | Де використовується |
|---|---|---|
| Підтвердження | `ACK\r` / `NAK\r` | Усі записи керування, налаштування та калібрування |
| Кадр даних | `(` + поля через пробіл + `\r` | Більшість запитів і зчитувань налаштувань |
| Кадр із `#` | `#` + поля + `\r` | `F`, `I` |
| З міткою | `BLAAA\r` | `BL` |
| Без префікса | `AAAA\r`, `AA BB CC\r` | `TCQN`, `DATE`, `TIME` |
| Розширене підтвердження | `(ACK\r` | `SNMP`, `SBMS` |

### 3.3 Зчитування налаштування

Більшість команд налаштування дозволяють зчитати значення. Для цього надсилають назву команди, а за нею **по одному `?` на кожен символ параметра**, причому крапка рахується як символ:

```
TCCV????\r   ->  (28.3\r        (шаблон <nn.n>, 4 символи)
CHGC???\r    ->  (020\r         (шаблон <nnn>)
TBAT?\r      ->  (0\r           (шаблон <n>)
UP?????\r    ->  (05000\r       (шаблон <nnnnn>)
```

Точний рядок запиту для кожної команди наведено в її розділі. `F` — виняток: її налаштування зчитується запитом номінальних даних `F\r` (§8.1).

### 3.4 Позначення, що використовуються в специфікації

- Групи великих літер (`AAA.A`, `BB.BB`, `KKKKK`) позначають позиційні поля. Кількість літер дорівнює кількості цифр, а крапка — це буквальна десяткова крапка.
- `b15…b0` та `c15…c0` — 16-символьні рядки з `0`/`1`. **Крайній лівий символ — це біт 15**.
- `<n>`, `<nn>`, `<nnn.n>` — параметри запиту.
- `?` у запиті — буквальний знак питання (див. §3.3).

## 4. Посібник з реалізації

> Усе в §4 є **[Прим. реалізації]**: наші рекомендації, виведені зі специфікації.

### 4.1 Цикл обміну

1. Відкрийте порт на 2400 8N1. Очистіть буфер прийому.
2. Надішліть `<cmd>\r`.
3. Читайте байти до `\r`. Використовуйте тайм-аут **≥ 500 ms**; рекомендовано 1000 ms, бо 2400 bps — це повільно. Найдовші кадри — `GPV` і `GPDAT`, близько 150 символів, на передачу яких за 2400 bps іде близько 0.6 с. Тому відраховуйте тайм-аут **від останнього отриманого байта**, а не від моменту надсилання запиту.
4. Видаліть кінцевий `\r` (і будь-який `\n`).
5. Класифікуйте відповідь: `ACK`, `NAK`, `(…`, `#…`, `BL…` або без префікса.
6. Надсилайте лише один запит за раз. Перш ніж надіслати наступний запит, дочекайтеся відповіді або тайм-ауту.

### 4.2 Розбір кадрів даних

- Видаліть префікс `(` або `#`, обріжте рядок, потім розбийте його за **послідовностями пробільних символів**. Деякі приклади в специфікації містять подвійні пробіли або пробіл після `(`, наприклад `( 361.0 360.0 360.0`.
- Зіставляйте токени з полями **за позицією**, використовуючи наведені нижче таблиці полів.
- **Будьте толерантними.** Приймайте менше або більше токенів, ніж задокументовано. Старіші прошивки повертають коротші кадри, а кілька прикладів у специфікації мають менше полів, ніж їхні шаблони (див. `GLINE` і `FAN` у §14). Відсутні поля мають ставати `null`, а не спричиняти помилку.
- Розбирайте числа з інваріантною культурою: десятковий роздільник — завжди `.`.
- Зберігайте бітові рядки як рядки або перетворюйте їх за формулою `bit(i) = s[15 - i] == '1'`.

### 4.3 32-бітні лічильники енергії

`GLINE`, `GOP` і `GPV` повідомляють значення лічильників енергії за весь час роботи у двох 16-бітних десяткових полях: поле «розширення» (старше слово), за яким іде поле молодшого слова. Специфікація описує їх як «двійкове зчеплення, що читається в десятковому вигляді»:

```
total = ext * 65536 + low          // обидва поля — десяткові числа 0..65535
energy_Wh = total * 10             // одиниця — десятки ват-годин
```

Добові лічильники — це окремі поля в тій самій одиниці (×10 Wh). Команда `Q\r` скидає всі ці лічильники (§7.5).

### 4.4 Запис

- Завжди перевіряйте наявність `ACK`. `NAK` означає, що значення поза діапазоном **або** команда не дозволена в поточному режимі роботи (§6).
- **[Прим. реалізації]** Після успішного запису зчитайте значення у формі з `?` (§3.3), щоб його підтвердити.
- Деякі налаштування залежать від інших налаштувань. Основні залежності:
  - `TCCV`, `TCFV`, `EOD` і `TBLV` діють лише тоді, коли тип батареї — користувацький (специфікація каже надсилати `TBAT2`; див. §14 щодо конфлікту TBAT 2/3).
  - Напруга CV (`TCCV`) має бути більшою за напругу буферного заряду (float) (`TCFV`).
  - `TCVT` діє лише тоді, коли режим заряду — примусовий 3-етапний (`CST02`).
  - `BSOCU`, `BSOCG` і `BSOCB` діють лише за працездатного зв'язку з BMS.
  - `TCDV` і `TDOT` потребують допоміжної плати подвійного виходу.
  - `ED1`, `F` і `SW` приймаються лише в режимі очікування або режимі мережі.

### 4.5 Рекомендований набір команд для моніторингу

| Призначення | Команди |
|---|---|
| Режим і несправності | `GMOD`, `GWS` |
| Мережа | `GLINE` |
| Вихід і навантаження | `GOP` |
| Батарея | `GBAT`, `BL`, `GCHG` (і `GBMS`, якщо підключено BMS) |
| PV | `GPV` |
| Температури | `GTMP` |
| Ідентифікація (одноразово) | `I`, `SVFW`, `F` |
| Системи паралельної роботи | `GPDAT<n>`, `GPSTS<n><m>`, `GPID<n>`, `GPPV<n>` |

За 2400 bps повний цикл наведених вище команд займає близько 3–5 с. Не опитуйте частіше, ніж здатен пропустити канал.

## 9. Команди налаштування

Загальна поведінка для всіх команд цього розділу:

- Інвертор відповідає `ACK\r` у разі успіху та `NAK\r` у разі невдачі.
- Форма зчитування налаштування використовує символи `?` (§3.3) і повертає `(value\r`.
- Діапазони напруги батареї залежать від номінальної напруги батареї (12 / 24 / 48 V).

## 10. Команди калібрування

> ⚠️ Калібрування змінює коефіцієнти вимірювання пристрою. Використовуйте ці команди лише в сервісних інструментах, ніколи
> у звичайному коді моніторингу.

### 10.1 BA0 — скидання калібрування напруги батареї

`BA0\r` → `ACK\r`. Відновлює стандартне калібрування напруги батареї. У прикладі специфікації вказано `BT0`; див. §14.

### 10.2 B1A\<nn.n\> — калібрування батареї, верхня точка

`B1A<nn.n>\r`, де nn.n — фактична напруга батареї, виміряна мультиметром, у V.
Приклад: `B1A21.0\r` → `ACK`.

### 10.3 B2A\<nn.n\> — калібрування батареї, нижня точка

`B2A<nn.n>\r`. Приклад: `B2A27.0\r` → `ACK`.

Калібрування батареї використовує **дві точки**. Щоб завершити його, надішліть і `B1A`, і `B2A`.

### 10.4 PA0 — скидання калібрування PV

`PA0\r` → `ACK\r`. Відновлює стандартне калібрування напруги PV.

### 10.5 PV\<nnn.n\> — калібрування напруги PV

`PV<nnn.n>\r`, де nnn.n — фактична напруга PV, виміряна мультиметром. Приклад: `PV150.0\r` → `ACK`.

### 10.6 Відносні підстроювання (±)

Формат: `<CMD>+<nn>\r` або `<CMD>-<nn>\r`, де nn = 00–99 сирих кроків. `+` збільшує виміряне
або відображуване значення, а `-` зменшує його. Поточне підстроювання зчитується командою `<CMD>???\r`, яка повертає
`(2048\r`. Підстроювання — це сирий регістр, і 2048, імовірно, є нейтральною серединою.

| Команда | Що калібрує | Параметр |
|---|---|---|
| `BUN±nn` | Напруга шини (відображувана) | 00–99 |
| `LVR±nn` | Напруга мережі | 00–99 |
| `VDR±nn` | Вихідна напруга | Точне: `+.x` / `-.x`, x = 1–9 → 0.1–0.9 V. Грубе: `+0x` / `-0x` → 1–9 V. |
| `OCR±nn` | Вихідний струм (відображуваний) | 00–99 |
| `VR±nn` | Напруга інвертора | Точне та грубе, як для `VDR`. Приклади: `VR+02` = +2 V, `VR+.2` = +0.2 V. |
| `IR±nn` | Струм інвертора | 00–99 |
| `DCR±nn` | DC-складова виходу | 00–99 |
| `CHI±nn` | Струм заряду | 00–99 |
| `LWT±nn` | Вихідна активна потужність (W) | 00–99 |
| `LVA±nn` | Вихідна повна потужність (VA) | 00–99 |

## 11. Розширені команди (плата SNMP / BMS)

Ці команди передаються між інвертором і зовнішньою платою централізованого моніторингу або BMS.
Тут обмін ініціює **інвертор**.

### 11.1 SNMP\n — рукостискання присутності

- Кожні 10 с інвертор надсилає `GSNMP`.
- Плата має відповісти `SNMP\n\r` протягом 10 с. Інвертор відповідає `(ACK\r`.
- Якщо 3 відповіді поспіль відсутні, інвертор вважає плату відключеною. Тоді він очищає дані BMS і блокує функцію зв'язку з BMS.

### 11.2 SBMS\n — передавання даних BMS

Плата надсилає такий кадр. Поля йдуть одне за одним без роздільника (знаки `+` у специфікації лише позначають межі):

```
SBMS\n XXXXX AAAAA BBBBB CCCCC DDDDD EEEEE FFFFF GGGGG HHHHH IIIII JJJJJ KKKKK LLLLLLLLLLLLLLLLLLLLLLLLL \r
```

Інвертор відповідає `(ACK\r`. Правила присутності з §11.1 також діють.

| Поле | Значення | Одиниця / значення |
|---|---|---|
| `XXXXX` | Стан протоколу BMS | `0x0000` = ініціалізація, `0x0001` = протокол Growatt, `0x0002` = протокол China Tower, `0x8000` = зв'язок із BMS втрачено |
| `AAAAA` | Стан батарейного блока | `0x0000` = один блок, `0x0100` = послідовно-паралельний блок, `0x0200` = послідовно-паралельний блок у процесі формування |
| `BBBBB` | Напруга батареї | 100 mV |
| `CCCCC` | Струм батареї | 10 mA, зі знаком |
| `DDDDD` | Температура батареї | 0.1 °C, зі знаком |
| `EEEEE` | SOC блока | 0.1 % |
| `FFFFF` | Залишкова ємність | 0.1 Ah |
| `GGGGG` | Номінальна ємність | 0.1 Ah |
| `HHHHH` | Інформація про несправності блока | |
| `IIIII` | Інформація про попередження блока | |
| `JJJJJ` | Максимальний струм заряду | 10 mA |
| `KKKKK` | Напруга CV | 100 mV |
| `L`×25 | Резерв | |

- Поля резерву та невизначені значення BMS надсилаються як **32767**.
- Інвертор читає інші поля, лише коли отримав дійсний стан протоколу. Якщо він не отримує дійсного протоколу BMS 10 с поспіль або отримує «зв'язок втрачено», він формує **попередження 56**.
- **[Прим. реалізації]** Специфікація не уточнює, чи `XXXXX` надсилається як десятковий чи як шістнадцятковий текст. Перевірте це на пристрої.

### 12.1 GCF — детальний стан несправностей

| | |
|---|---|
| Запит | `GCF\r` |

| Мітка | Біти | Значення |
|---|---|---|
| `BT` | 16 | Біти стану батареї |
| `RL` | 16 | Біти стану мережі |

| `I2` | 16 | Біти стану інвертора 2 |

**[Прим. реалізації]** Розбирайте кожну групу за її двобуквеною міткою, а не за позицією.

## 14. Відомі проблеми в документі виробника

Це помилки та суперечності, виявлені в оригіналі. Обробляйте їх у коді захисно.

| # | Де | Проблема | Рекомендована обробка |
|---|---|---|---|
| 1 | Приклад `GLINE` | У прикладі 9 полів; у шаблоні — 13. | Толерантний позиційний розбір (§4.2) |
| 2 | `FAN???` | Шаблон `(AAA BBB C` має 3 поля; приклад — 5. | Використовуйте 5-польову структуру з прикладу |
| 3 | `TIME` | Приклад запису використовує `DATE051203` для встановлення часу. | Використовуйте `TIMEhhmmss` |
| 4 | `BA0` | У прикладі вказано `BT0`. | Надсилайте `BA0` |
| 5 | `VDR` / `VR` | Синтаксис грубого підстроювання показано як `Vn-0x`. | Читайте як `<CMD>-0x` |
| 6 | `GCC` | У заголовку вказано `<nn>`, але діапазон і приклад використовують 3 цифри. | Надсилайте 3 цифри (`GCC050`) |
| 7 | `CHGC` | Значення за замовчуванням вказано як «1». | Зчитуйте фактичне значення |
| 8 | `TCQV` | Текст прикладу скопійовано з `BTG` («повернення на мережу 25 V»). | Ігноруйте це формулювання |
| 9 | `V` | Посилається на «команду HV, див. 6.18»; правильне посилання — §9.26. | — |
| 10 | `TBAT` vs `TCCV/TCFV/EOD/TBLV` | `TBAT` визначає 3 = користувацька, але залежні команди кажуть «надішліть `TBAT2`» (2 = літієва). | Перевірте на пристрої. Імовірно, користувацька = 3. |
| 11 | `GFAIL` | Поле `GG.GG` не описано. В описі вказано `CCCC`, а в шаблоні — `CCCCC`. У заголовку сказано «для пристрою `<n>`», але команда не має параметра. | Зіставляйте за позицією (§8.21) |
| 12 | `GBMS` | Одиницею SOC вказано «0.1 Ah». | Вважайте SOC у 0.1 % |
| 13 | Енергія `GLINE` | Одиниця — «десятки ватів» (не Wh). | Вважайте ×10 Wh, як у `GOP`/`GPV` |
| 14 | `SVFW` | Шаблон закінчується на `\r\r`. | Приймайте один або два CR |
| 15 | Таблиця §6 | Рядок дії «байпас або очікування» вдруге містить `SOFF`. | Мається на увазі `SPOFF` |
| 16 | `TE` | Прапорця `W` немає. Редакція 18 згадує `a b c`, яких немає в переліку. | Обробляйте невідомі літери |
| 17 | `BTB` 48 V | Значення за замовчуванням 54.0 V поза вказаним діапазоном 44.0–52.0 V. | Зчитуйте фактичне значення |
| 18 | `GCF` | Група `P1` має 17 бітів; інші групи — 16. | Розбирайте за міткою, а не за довжиною |
| 19 | `F` | Поле кількості елементів описано як «×120», з двома різними форматами. | Розбирайте як число з плаваючою крапкою |
| 20 | Таблиця команд | Кількість за категоріями («24 запити», «40 налаштувань») не точно збігається з розділами. `CFG` фігурує і серед налаштувань, і серед запитів. | — |

## 15. Глосарій

| Термін | Значення |
|---|---|
| Головний пристрій (Host) | ПК або контролер, що надсилає команди (上位机) |
| Режим мережі (Line mode) | Навантаження живиться від мережі (електромережі) |
| Режим батареї (Battery mode) | Навантаження живиться інвертором від батареї або PV |
| Байпас (Bypass) | Вихід підключено безпосередньо до мережі |
| CV | Етап заряду постійною напругою (абсорбція) |
| Буферний заряд (Float) | Етап підтримувального заряду (буферний заряд) |
| EQ | Вирівнювальний заряд |
| PBG | Пріоритет виходу PV → батарея → мережа (`OPR02`) |
| APP / UPS | Режими виходу: побутові прилади або UPS (`OPM`) |
| PFC | Каскад корекції коефіцієнта потужності, перетворювач з боку мережі |
| INV | Каскад інвертора, перетворювач DC→AC |
| DC/DC | Перетворювач заряду/розряду батареї |
| MPPT | Відстеження точки максимальної потужності входу PV |
| BMS | Система керування батареєю (для літієвих блоків) |
| SOC | Рівень заряду, % |
| Система паралельної роботи | Кілька інверторів, що спільно живлять навантаження. Пристрої адресуються через `<n>`. |
